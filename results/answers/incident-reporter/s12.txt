## 3. Root cause

- **`api`** — The Deployment manifest references a non-existent image tag `nginx:1.99.99-does-not-exist`. The registry returns `not found`, so the image can never be pulled; kubelet backs off forever.
- **`batch`** — An invalid resource request: `cpu: "16"` means 16 CPU *cores* (not 16 millicores, which would be `16m`). Neither of the two nodes has 16 free cores, and preemption cannot help, so the scheduler leaves the pod `Pending`.
- **`cache`** — The container is asked to allocate 200 MB (`--vm-bytes 200M`) but its memory limit is `64Mi`. The kernel OOM-kills the process immediately after start (exit 137); the pod loops in `CrashLoopBackOff`.
- **`worker`** — The container's own entrypoint is `/bin/sh -c "echo 'config file /etc/worker/config.yaml not found'; exit 1"`: it deliberately prints that message and exits 1. The required config file is not mounted/provided to the container, so the process fails on every restart.
- **`checkout`** — Selector mismatch: the Service selects `app=checkout`, but no workload in the namespace carries that label. With an empty EndpointSlice, kube-proxy programs no backends, so the ClusterIP resolves but every connection to port 80 is refused.

## 4. Fix

**`api`** — point the Deployment at an image tag that exists (registry-side note: the tag was never published):
```
kubectl -n demo-broken set image deployment/api api=nginx:1.27
```

**`batch`** — correct the CPU request from 16 cores to a realistic value:
```
kubectl -n demo-broken patch deployment batch --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/containers/0/resources/requests/cpu","value":"100m"}]'
```

**`cache`** — either raise the limit above the workload's allocation or lower the demand:
```
kubectl -n demo-broken set resources deployment/cache --limits=memory=512Mi
# or lower the demand in the manifest: --vm-bytes 32M with the existing 64Mi limit
```

**`worker`** — provide the missing configuration, e.g. mount it from a ConfigMap named `worker-config` and remove the failing placeholder command:
```
kubectl -n demo-broken create configmap worker-config --from-file=config.yaml=./config.yaml
kubectl -n demo-broken patch deployment worker --type=json -p='[
  {"op":"add","path":"/spec/template/spec/volumes","value":[{"name":"config","configMap":{"name":"worker-config"}}]},
  {"op":"add","path":"/spec/template/spec/containers/0/volumeMounts","value":[{"name":"config","mountPath":"/etc/worker","readOnly":true}]}
]'
```
(The current command must also be replaced with the real worker entrypoint — as written it always exits 1 regardless of the file.)

**`checkout`** — make the selector match the workload that should serve it. If `web` (`app=web`, 3/3 Running) is the intended backend:
```
kubectl -n demo-broken patch service checkout -p '{"spec":{"selector":{"app":"web"}}}'
```
Otherwise deploy the missing `app=checkout` workload. Verify afterwards:
```
kubectl -n demo-broken get endpoints checkout
```
which should list the pod IPs on port 80.
